# `bestie.framework.orm`

Database abstraction framework for typed persistence and query workflows.

## Purpose

`orm` provides structured mapping between domain models and relational data while preserving explicit query intent and transaction boundaries.

It aims to reduce boilerplate around:

- Entity persistence
- Query construction
- Transaction management
- Repository organization

## Layering and Dependencies

`orm` is part of `std-framework` and builds on:

- `bestie.api.db`
- `bestie.api.io` (optional for migration scripts)
- `bestie.lib.util` / `bestie.lib.collections`

Import style (explicit per-symbol):

```bestie
import bestie.framework.orm.Entity
import bestie.framework.orm.Table
import bestie.framework.orm.Column
import bestie.framework.orm.Id
```

## Core Concepts

- `Entity`: persistence-aware domain type, declared with `@Entity`.
- `Repository`: typed data access protocol.
- `Session`: unit of interaction with the DB backend.
- `Transaction`: explicit boundary for consistent writes.
- `Query`: composable and typed query builder.

## Annotation-Driven Mapping

Entity mapping is declared through annotations. The compiler validates schema metadata and generates serialization/deserialization code at compile time using compile-time reflection (`bestie.framework.reflection`, see `std-framework/reflection.md`) — no runtime reflection.

### Entity Annotations

| Annotation | Target | Effect |
|---|---|---|
| `@Entity` | class | Marks as a persistence-mapped type |
| `@Table(name)` | class | Maps to a specific table name (defaults to class name) |
| `@Column(name?)` | field | Maps field to a column; name defaults to field name |
| `@Id` | field | Declares the primary key |
| `@GeneratedId` | field | Primary key is generated by the database |
| `@Nullable` | field | Column allows NULL; field type must be `T ?` |

### Relationship Annotations

| Annotation | Target | Effect |
|---|---|---|
| `@ManyToOne(foreignKey)` | field | Many-to-one association |
| `@OneToMany(mappedBy)` | field | One-to-many association; lazy by default |
| `@OneToOne(foreignKey)` | field | One-to-one association |
| `@Eager` | field | Forces eager loading on a relationship |

### Example Entities

```bestie
import bestie.framework.orm.Entity
import bestie.framework.orm.Table
import bestie.framework.orm.Column
import bestie.framework.orm.Id
import bestie.framework.orm.GeneratedId
import bestie.framework.orm.ManyToOne
import bestie.framework.orm.OneToMany
import bestie.framework.orm.Eager
import bestie.lib.datetime.DateTime

@Entity
@Table("users")
class User {
    @Id @GeneratedId
    val id: int

    @Column("email")
    val email: str

    @Column
    val createdAt: DateTime

    @ManyToOne("team_id")
    val team: Team
}

@Entity
@Table("teams")
class Team {
    @Id @GeneratedId
    val id: int

    @Column
    val name: str

    @OneToMany(mappedBy = "team")
    @Eager
    val members: list<User>
}
```

## Repository Pattern

Repositories are declared as protocols extending `Repository<Entity, IdType>`:

```bestie
import bestie.framework.orm.Repository
import bestie.framework.orm.Transaction

protocol UserRepository ext Repository<User, int> {
    fun findByEmail(email: str): User ?
    fun listByTeam(teamId: int): list<User>
    fun insert(user: User, tx: Transaction): void
}
```

The `orm` framework generates a default implementation. Custom query methods may be backed by typed query builders or inline SQL.

## Transaction Model

- Transactions are explicit (`begin`, `commit`, `rollback`).
- Nested transactions use savepoints when supported by the driver.
- Auto-commit behavior must be opt-in.

```bestie
import bestie.framework.orm.transaction
import bestie.lib.datetime.DateTime

fun createUser(repo: UserRepository, email: str): void {
    transaction(fun(tx: Transaction): void {
        repo.insert(User.new(email: email, createdAt: DateTime.now()), tx)
    })
}
```

## Query Builder

```bestie
import bestie.framework.orm.Session

fun activeUsersInTeam(session: Session, teamId: int): list<User> {
    return session.query(User)
        .where(fun(u: User): bool { return u.team.id == teamId })
        .orderBy(fun(u: User): DateTime { return u.createdAt }, descending: true)
        .limit(50)
        .fetch()
}
```

Queries are typed and validated against entity metadata at compile time where possible.

## Non-Goals

- No runtime schema guessing via reflection
- No hidden write flush at arbitrary points
- No bypass of explicit transaction semantics
